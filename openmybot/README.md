# OpenMyBot

OpenMyBot is the local foreground product assembled from the shared OpenBot engine. Wrok Bot and OpenMyBot are maintained in the same workspace with separate product entry points.

The current command surface is `openmybot init --pg-bin-dir <absolute-directory>`, `openmybot daemon`, `openmybot status [--run <run-id>]`, `openmybot pair <channel> --workspace <absolute-directory> [--run-deadline <seconds>] [--host <host>]`, `openmybot bindings list`, `openmybot bindings revoke <binding-id>`, `openmybot bindings reconfirm <binding-id>`, `openmybot bindings reset-thread <binding-id> --ack-unknown <run-id>`, `openmybot bindings receiver <channel>` (reads one line of standard input per credential field the channel's plugin declares), `openmybot bindings host <host> --workspace <absolute-directory> [--run-deadline <seconds>]`, `openmybot approve <permission-id>`, `openmybot deny <permission-id>`, `openmybot cancel <run-id>`, `openmybot plugins list`, `openmybot plugins add <absolute-directory>`, `openmybot plugins add --built-in <telegram|feishu>` (installs a first-party channel plugin from the binaries shipped beside `openmybot`), `openmybot plugins remove <name>` and `openmybot mcp [--host <host>]`. `<host>` is `crabcode` or `claude` (Claude Code); `wrok` and `wrokcode` are accepted as `crabcode`, and `--host` defaults to `crabcode`. Every command except `openmybot mcp` accepts `--data-dir <absolute-directory>` and `--json`; `openmybot mcp` is started by a host, serves five MCP tools on standard input and output, and accepts `--data-dir <absolute-directory>` and `--host <host>` but not `--json`. Data directory selection uses that argument, then `OPENMYBOT_DATA_DIR`, then `$HOME/Library/Application Support/OpenMyBot`.

Provide PostgreSQL 17 binaries, including `postgres` and `initdb`, in the explicit binary directory. Building the shared server dependencies also requires xmlsec1, libxml2 and OpenSSL. Build a release with `cargo build --release -p omb-cli -p omb-channels` and without `--all-features`, which would add test-only options to the channel plugin binaries. Initialization creates an independent private PostgreSQL cluster and random local keys. The daemon runs in the foreground, supervises that cluster, and exposes a Unix socket protected by the current user's identity and a token rotated at every start. Stop it with SIGINT or SIGTERM.

The data directory's `config.toml` lists the allowed workspace directories in a top-level `workspace_roots` array and configures each host in its own `[hosts.<host>]` section, whose `binary` is the absolute path of that host's executable. A host without a `binary` refuses every start of its runs with `spawn_failed`, and `pair --host` and `bindings host` for it answer `host_not_configured`. The earlier layout with `workspace_roots` inside `[hosts.crabcode]` is refused with `config_invalid`.

Status reports process, PostgreSQL, version, deployment and authentication-failure facts, a channel segment and the installed channel plugins. Channels run as out-of-process channel plugins that `openmybot plugins add` installs into the data directory; the daemon supervises their processes. The dispatcher, outcome delivery through the channel plugins, the host driver for CrabCode and Claude Code, `openmybot mcp` and the host projections for CrabCode and Claude Code are delivered. Each host runs only the versions its compatibility window accepts; the Claude Code window is empty until a real-machine recheck is recorded. The embedded composition package does not establish model availability. No background launch service is installed.
